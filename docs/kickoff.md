# Corthex Classmate 킥오프

- 날짜: 2026-09-01
- 작성자: Codex (대화 합의 정리)
- 참여자: 사용자, Codex
- 깊이: standard

## 목표

- Java·Spring 개발 입문자가 하루 최대 8교시의 수업을 들을 때, 이해하지 못한 순간에 수업을 더 놓치지 않으면서 AI에게 짧고 근거 있는 설명을 받고 빠르게 수업으로 돌아가게 한다.
- Tiro 전사, Google Meet 공유 화면, IntelliJ의 읽기 전용 코드 문맥, 사용자 질문·표시를 연결해 수업 사건을 기록한다.
- 교시가 끝난 뒤 중요한 개념·코드·질문·막힌 지점·근거가 빠지지 않은 상세 복습자료를 만들고, 하루 단위 학습 허브로 연결한다.
- 첫 사용자는 프로젝트 사용자 본인이며, 사용감이 검증된 뒤 친구가 설치하고 자신의 Codex 또는 Claude를 연결해 쓸 수 있는 형태로 확장한다.

## 성공 기준

| 기준 | 어떻게 확인하나 |
|---|---|
| 수업 중 한 번의 행동으로 도움을 요청할 수 있다 | 골든 시나리오에서 `방금 내용 쉽게 설명`과 같은 행동으로 질문 시점의 전사·화면·코드 문맥이 묶이는지 확인한다. |
| 첫 답변이 이해 회복과 수업 복귀를 돕는다 | 한 문장 결론이 먼저 나오고, 자세한 설명은 선택적으로 펼쳐지며, `수업으로 돌아가기` 흐름이 있는지 확인한다. |
| 60분 교시의 중요 내용이 과도하게 압축되지 않는다 | 교시별 자료에 수업 목표, 개념 관계, 코드 흐름, 사용자 막힘, 오류, 확인 문제, 근거 타임라인이 필요한 만큼 포함되는지 확인한다. |
| 하루 8교시를 탐색 가능한 구조로 제공한다 | 교시별 상세 자료 8개와, 반복해서 막힌 개념·교시 간 연결·다음 복습 행동을 보여 주는 하루 허브가 연결되는지 확인한다. |
| AI가 확인한 사실과 추론을 구분한다 | 각 답변과 복습 항목에 전사·Meet·IntelliJ·사용자 입력·추론의 출처와 자료 최신성이 표시되는지 확인한다. |
| 일부 연결이 실패해도 기록이 계속된다 | Tiro 지연, Meet 장면 부재, IntelliJ 또는 AI 연결 끊김 시 무엇이 멈추고 무엇이 계속 저장되는지 확인한다. |
| 디자인이 학습 목적에 맞게 달라질 수 있다 | 차분한 학습형을 기본으로 하되 코드 실습형·시각 개념형·이야기형·시험 복습형을 목적에 따라 선택할 수 있는지 확인한다. |

## 대상

- 1차 대상: Windows PC, Chrome, IntelliJ로 Java·Spring 수업을 듣는 개발 입문자
- 2차 대상: 같은 프로그램을 설치하고 자신의 Codex 또는 Claude를 연결해 쓰려는 친구
- 주요 사용 조건: 하루 최대 8교시, 교시당 약 60분

## 범위

- 한다:
  - Google Meet 옆 Chrome 사이드패널에서 동작하는 라이브 학습 동행 UX를 검토한다.
  - iPhone Tiro가 잡은 선생님 음성 전사, Meet 화면, IntelliJ 읽기 전용 문맥을 질문 시점에 연결한다.
  - Codex 또는 Claude를 선택 가능한 라이브 튜터로 연결하는 경로를 검토한다.
  - 평상시에는 조용히 기록하고, 질문·막힘 표시 때 설명하는 흐름을 만든다.
  - 교시별 상세 복습자료와 하루 학습 허브를 만든다.
  - 수업 원본과 생성된 설명을 분리하고, 근거·추론·자료 최신성을 표시한다.
  - 로컬 우선 기록과 상세 HTML 복습자료를 기본 방향으로 삼는다.
  - 첫 골든 시나리오로 `IoC 컨테이너와 new를 직접 사용하는 코드` 장면을 사용한다.
- 안 한다:
  - 첫 PoC에서 전체 모바일 앱을 별도로 설계하지 않는다.
  - AI가 하루 8시간 동안 계속 추론하거나 먼저 긴 설명을 내보내는 방식을 기본으로 하지 않는다.
  - 라이브 튜터에게 IntelliJ 파일 수정·명령 실행·터미널 실행을 맡기지 않는다.
  - 전체 수업 영상을 매번 별도 복제하는 방식을 기본값으로 두지 않는다.
  - UX 방향을 고르기 전에 프로덕션 구현·배포를 시작하지 않는다.
  - 모든 복습자료에 하나의 시네마틱 디자인을 강제하지 않는다.

## 골든 시나리오

- 주제: IoC 컨테이너와 객체 생성 책임
- 사용자 의문: `new로 만들던 것을 컨테이너가 만든다는 게 무슨 뜻이지? 결국 누군가는 new를 해야 하는 것 아닌가?`
- 시작 상태: Tiro, Meet 화면, IntelliJ 읽기 문맥, AI 튜터, 로컬 기록이 정상
- 사용자 행동: `방금 내용 쉽게 설명`
- 문맥 묶음: 직전 Tiro 전사, 질문 시점 Meet 장면, IntelliJ 현재 파일·코드 범위, 최근 주제, 이전 막힘 기록
- 첫 답변 원칙: 한 문장 결론을 먼저 제공하고, 그림·현재 코드·테스트 이유·수업 복귀를 선택적으로 제공
- 종료 행동: `이해했어요`, `아직 헷갈려요`, `복습에 저장하고 수업으로`
- 교시 종료 결과: 선생님 설명 흐름, 직접 생성 코드, 컨테이너 생성 코드, 의존 관계, 사용자 막힘, 튜터 설명, 확인 문제, 근거 타임라인

## 숨은 전제

| 전제 | 안 맞을 수 있는 이유 | 판정 |
|---|---|---|
| 라이브 튜터가 8시간 내내 계속 추론해야 한다. | 기록은 저비용으로 계속하고 질문·개념 전환 때만 모델을 호출해도 목표를 달성할 수 있다. | 기본 전제로 사용하지 않음 |
| 복습자료가 길수록 좋다. | 분량보다 개념·코드·막힘·근거의 누락 여부가 중요하다. | 내용 coverage로 평가 |
| 라이브 패널과 복습자료가 같은 디자인이어야 한다. | 라이브는 짧고 조용해야 하고 복습자료는 상세하고 탐색 가능해야 한다. | 서로 다른 정보 구조 허용 |
| 각 역할은 반드시 별도 Agent여야 한다. | 초기에는 한 Agent가 여러 역할을 순서대로 수행해도 된다. | PoC 결과를 보고 분리 여부 결정 |

## 위험

| 위험 | 현재 대응 방향 |
|---|---|
| Tiro가 기술 용어를 잘못 전사한다. | 화면·코드·수업자료와 교차 확인하고 불확실한 단어를 표시한다. |
| 질문 시점의 Meet 화면 또는 IntelliJ 문맥이 오래됐다. | 자료별 최신 시각을 기록하고, 오래된 자료를 근거처럼 확정하지 않는다. |
| AI 답변이 길어 다음 수업을 더 놓친다. | 한 문장 결론, 선택적 펼치기, 명시적인 수업 복귀 행동을 둔다. |
| 하루 수업이 한 장 요약으로 과도하게 압축된다. | 교시별 상세 자료와 coverage 검사를 기본으로 한다. |
| 모델 구독 한도 또는 연결 장애가 생긴다. | 전사·화면·코드 기록과 AI 응답을 분리해 기록은 계속되게 한다. |
| 디자인 도구의 기능이 Paseo 좌석에서 제공되지 않는다. | 실행 시 기능을 실측하고 `/design`·`$imagegen`·정적 HTML 순으로 대체한다. |
| 여러 Agent를 일찍 분리해 시스템이 과도하게 복잡해진다. | 첫 PoC에서는 논리 역할만 분리하고 실제 병목이 확인될 때만 프로세스를 나눈다. |

## 의존

- Paseo의 Claude 2좌석·Codex 2좌석·3라운드 UX/UI 발산 결과
- Tiro 실시간 전사 공유 또는 API 경로의 실제 지연·안정성 확인
- Google Meet 탭 장면을 사용자가 허용한 범위에서 수집하는 PoC
- IntelliJ 프로젝트 파일·현재 문맥의 읽기 전용 연결 PoC
- 설치된 Codex 또는 Claude를 안전하게 연결하는 로컬 provider 경로
- 실제 IoC 수업 전사·장면·코드·사용자 질문으로 만든 검증 자료
- Codex 작업 `Design integrated coding study path` (`01a05bb9-9f23-79b3-800d-b9895244151c`)가 정한 프로젝트 단계와 `예측 → 값 하나 추적 → 힌트 없이 유사 기능 작성 → 다음 날 재현` 성취 기준
