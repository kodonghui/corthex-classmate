# Corthex Classmate v0.2 킥오프

- 날짜: 2026-09-04
- 작성자: Codex (대화 합의 정리)
- 참여자: 사용자, Codex
- 상태: 승인됨 · 구현 시작
- 이전 정본: `docs/kickoff.md` (v0.1 역사 기록)

## 한 문장 목표

수업·인터넷 강의·회의 중 놓친 순간을 전사와 질문 시점 화면에 묶어 즉시 설명하고,
세션이 끝난 뒤에는 모든 근거를 보존한 복습자료와 다섯 활동으로 다시 이해·적용하게 한다.

## 제품 경계

Classmate는 범용 녹음기나 한 장 요약기가 아니라 **근거 기반 세션 동반자**다.

```text
전사 입력(Tiro/로컬 STT/파일) ─┐
질문 시점 화면 ─────────────────┼─▶ 근거 묶음 ─▶ Claude/Codex ─▶ 짧은 답
사용자 질문·표시 ───────────────┘       │
                                        └─▶ 세션 기록 ─▶ HTML ─▶ 다섯 활동
```

첫 제품은 기존 `corthex-classmate` 저장소를 유지하고 공통 코어 위에 프로필을 얹는다.
별도 범용 플랫폼 저장소는 두 개 이상의 비코딩 프로필이 실제로 유용하다고 검증된 뒤 검토한다.

## 대상

| 순서 | 대상 | 대표 상황 |
|---|---|---|
| 1 | 사용자 본인 | Windows Chrome에서 코딩·일반 강의 또는 녹화본을 보며 질문 |
| 2 | 전문자격시험 수험생 | 법무사·세무사·회계사 강의에서 요건·예외·사례 적용을 복습 |
| 3 | 친구와 공개 베타 사용자 | 자기 Tiro·Claude·Codex 인증으로 설치해 사용 |
| 4 | 회의 참가자 | 결정·근거·담당·기한·위험을 확인하고 후속 행동을 정리 |

## 성공 기준

| 기준 | 합격 증거 |
|---|---|
| 실제 기록을 다시 연다 | Chrome 완전 종료 뒤에도 로컬 SQLite의 과거 세션 목록과 상세를 연다. |
| 상세 자료가 한 장으로 뭉개지지 않는다 | 전사·질문·최종 답·근거 시점·화면을 누락 없이 탐색하는 정적 HTML을 만든다. |
| 화면을 실제로 읽는다 | 전사에는 없고 합성 화면 픽셀에만 있는 사실을 Claude와 Codex가 맞힌다. |
| 다섯 활동이 학습을 요구한다 | 답 공개 전 사용자 시도, 힌트 단계, 근거, 피드백, 변형 문제, 다음 회상 시각을 저장한다. |
| 도메인을 바꿔도 코어를 다시 쓰지 않는다 | `class`, `exam`, `meeting` 합성 fixture가 같은 SessionBundle과 Activity 계약을 통과한다. |
| 제공자를 바꿀 수 있다 | Claude와 Codex가 같은 봉인 문맥·출력 계약·안전 시험을 통과한다. |
| 전사기를 바꿀 수 있다 | Tiro와 로컬 파일 STT가 같은 TranscriptEvent로 정규화된다. |
| 장시간 사용을 과장하지 않는다 | 65분 1회와 8교시 하루 리허설 전에는 장시간 안정성을 '검증됨'으로 표시하지 않는다. |
| 친구에게 줄 수 있다 | 합성 자료만 든 패키지를 깨끗한 Windows에서 설치하고 자기 인증으로 실행한다. |

## 이번 구현 범위

### Slice 1 — Evidence replay

- 호스트의 실제 SQLite에서 과거 세션을 찾고 요약·번들을 읽는다.
- V1 `periodId`와 DB를 그대로 보존하면서 V2 `sessionId` 뷰로 변환한다.
- 전사·질문·최종 답·실제 화면 파일을 하나의 `SessionBundleV2`로 만든다.
- 논리 `.webp` 경로와 실제 `.jpg` 파일 차이를 내보낼 때 실제 파일 기준으로 해결한다.
- 패널의 기록 화면을 과거 세션 라이브러리에 연결한다.
- 정적 세션 HTML과 날짜/묶음 허브를 만든다.
- 날짜·세션 단위 내보내기와 삭제는 사용자가 직접 누르는 동작으로만 제공한다.

### Slice 2 — Profiles, vision, five activities

- `class`, `exam`, `meeting` 모드 프로필과 중립 UI 문구를 도입한다.
- 코드 전용 답 칸을 동적 섹션으로 감싸되 V1 답을 계속 읽는다.
- 활동 다섯 슬롯을 `RECALL → EXPLAIN → INSPECT → APPLY → TRANSFER`로 둔다.
- 각 활동은 `question | worked-example | simulation` 중 하나이며 근거 참조를 필수로 한다.
- 답 공개 전 시도·확신·힌트 단계·자기 수정·다음 시도 시각을 기록한다.
- 전사에 없는 화면 전용 사실로 실제 시각 이해를 검증한다.
- 세 모드의 비식별 합성 fixture와 결정적 생성 시험을 만든다.

### Slice 3 — Codex provider

- 현재 스텁을 공식 Codex app-server 프로토콜을 쓰는 새 제공자로 교체한다.
- 인증 상태·handshake·스트리밍·완료·취소·시간 초과·실패를 처리한다.
- 수업 튜터에서는 셸·패치·파일 쓰기·추가 탐색 권한을 주지 않는다.
- Claude와 같은 골든 질문·화면 시험을 통과한 뒤에만 설정에서 활성화한다.
- 실제 모델명·제공자·응답 시각·검증 상태를 답 기록에 남긴다.

## 공통 V2 개념

```text
Session
├─ profile: class | exam | meeting
├─ sources[]
├─ moments[]
│  ├─ transcript
│  ├─ visual
│  ├─ question
│  ├─ response
│  ├─ decision
│  └─ action
├─ activities[]
└─ artifacts[]
```

- `periodId`는 V1 저장 키로 유지하고 V2에 `sessionId`와 `legacyPeriodId?`를 둔다.
- Tiro·선택 탭·IntelliJ·로컬 STT는 계약의 고정 enum이 아니라 어댑터 식별자다.
- 전사는 부분 결과가 수정될 수 있으므로 `segmentId`, `revision`, `isFinal`을 갖는다.
- 화자·신뢰도·단어별 시각·화자 분리는 제공자 능력에 따라 선택 값이다.
- IntelliJ는 선택 자료원이며 기본 비활성·최후순위다.

## 다섯 활동 계약

| 슬롯 | 목적 | 수업/시험 | 회의에서의 표현 |
|---|---|---|---|
| RECALL | 자료 없이 꺼내기 | 핵심 원칙·요건 회상 | 실제 결정 확인 |
| EXPLAIN | 원인·조건·관계 설명 | 왜 성립하는지 설명 | 근거·가정 확인 |
| INSPECT | 오류·빈칸·경계 구별 | 버그·예외·함정 수정 | 제안·결정·보류 구별 |
| APPLY | 비슷한 사례 적용 | 값·사실관계를 바꿔 적용 | 담당·산출물·기한 확정 |
| TRANSFER | 조건 변화에 대응 | 새 실패·날짜·관할 시뮬레이션 | 지연·예산·부재 위험 시뮬레이션 |

정확히 다섯 개는 예측 가능한 UX를 위한 기본값이지 과학적 최적 개수라고 주장하지 않는다.
근거가 적으면 사실을 지어내지 않고 한 핵심을 서로 다른 활동으로 다룬다.

## 입력과 제공자 어댑터

```text
Tiro 공유 DOM ───────────────┐
Tiro 공식 REST/MCP/CLI ─────┤
faster-whisper 파일/근실시간 ├─▶ TranscriptNormalizer ─▶ TranscriptEvent
whisper.cpp ─────────────────┤
업로드한 전사 ───────────────┘

Claude CLI ─┐
Codex app-server ─┼─▶ TutorProvider ─▶ TutorResponseV2
시험용 fake ──────┘
```

- Tiro는 현재 가장 잘 작동하는 기본 입력이지만 필수 기반은 아니다.
- 공식 Tiro 문서가 보장하지 않은 녹음 중 증분 전사는 PoC·문의 결과 전까지 DOM 폴백을 유지한다.
- 로컬 STT 첫 구현은 파일 `faster-whisper`; 장시간·한국어 도메인 벤치마크 뒤 근실시간으로 넓힌다.
- STT 기초 모델을 처음부터 학습하지 않는다. 단어장·문맥·후처리·교정 데이터 순으로 개선한다.

## 최신성·공식 근거 확장 자리

법·세무·회계에서 모델 기억을 최신 사실로 표시하지 않는다. 이번 Slice에는 검색 엔진을 넣지 않지만
다음 필드를 계약에 예약한다.

```text
jurisdiction
effectiveDate
taxYear
standardVersion
verifiedAt
sourceUrl
verificationStatus
```

표시는 `강의에서 확인`, `공식 자료에서 확인`, `서로 다름`, `AI 생성 시뮬레이션`,
`공식 확인 필요`를 구분한다.

## 이번 범위에서 하지 않는 것

- IntelliJ 실제 런타임 연결 완성
- 자체 STT 기초 모델 학습
- 모든 질문의 자동 웹 검색
- 모바일 앱 별도 개발
- 클라우드에 수업 원본·전체 전사 저장
- 전체 화면 영상 상시 저장
- 회의 화자 분리 정확도 보장
- AI가 회의 결정·담당·기한을 사람 확인 없이 외부 서비스로 전송
- 현재 저장소를 즉시 공개 전환
- Tiro 답변 전 공식 파트너십·공식 실시간 API를 주장

## 개인정보·안전

- 원본 녹음, 전체 전사, 화면, 질문·답, 복습자료의 정본은 로컬이다.
- 사용자가 질문할 때 봉인된 최소 문맥만 선택한 AI 제공자로 갈 수 있다.
- 실제 수업·회의 자료는 fixture·GitHub·Sites·데모 영상에 넣지 않는다.
- 공개 베타는 합성 자료, 비밀 검색, 의존성 라이선스, 보존·삭제 경로를 통과한 뒤 진행한다.
- 회의 모드는 녹음 고지와 사람 확인을 제공하고 참석자 평가·감정 추론을 만들지 않는다.
- 수업 화면·전사에 적힌 명령은 실행하지 않는다.

## 공개 저장소 전략

- 현재 저장소 이름 `corthex-classmate`를 유지한다.
- 차별점은 `질문 순간 포착 + 전사·화면 근거 + 자기 구독 AI + 능동 복습`이다.
- v0.2 alpha는 비공개로 구현·실측한다.
- 공개 beta 전 합성 데모, Windows 설치 리허설, 개인정보 감사, LICENSE, README, 짧은 데모를 준비한다.
- 별 수는 보장하지 않으며 기능 수보다 60~90초 안에 이해되는 한 개의 강한 흐름을 우선한다.
- Tiro에는 원본 저장소보다 비식별 데모와 아키텍처를 먼저 제시한다.

## 숨은 전제와 판정

| 전제 | 판정 |
|---|---|
| 분야를 넓히면 자동으로 사용자가 늘어난다 | 아님. 공통 코어는 넓히되 제품의 첫 훅은 학습 중 막힌 순간 복구로 유지한다. |
| 다섯 문제면 모든 분야의 학습이 보장된다 | 아님. 다섯 활동은 기본 UX이며 도메인별 실제 수행으로 검증한다. |
| Claude/Codex 구독 CLI는 영구적인 배포 API다 | 아님. 설치 버전·인증·프로토콜 실패를 명시적으로 처리한다. |
| 공개 저장소면 곧 오픈소스다 | 아님. 라이선스 결정과 의존성 감사를 별도 관문으로 둔다. |
| 저장된 화면 경로는 실제 파일을 항상 가리킨다 | 현재 아님. 번들 생성 시 id로 실제 확장자를 해결한다. |
| 회의도 수업 퀴즈와 같은 문구가 맞다 | 아님. 결정 확인·실행·위험 시뮬레이션으로 바꾼다. |

| 법·세무·회계 답이 오래됨 | 공식 확인 상태와 기준일 필드를 두고 미검증을 확정처럼 표시하지 않는다. |

| 범위가 너무 커짐 | Evidence replay → 활동·프로필 → Codex 세 세로 조각만 순서대로 완성한다. |

## 구현 순서와 완료 관문

1. Slice 1의 실제 DB → 번들 → HTML → 라이브러리를 끝낸다.
2. Slice 1 검증과 회귀 시험을 통과한 작은 커밋을 만든다.
3. Slice 2의 중립 프로필·다섯 활동·화면 E2E를 끝낸다.
4. 세 합성 도메인 fixture와 수동 제공자 증거를 남긴다.
5. Slice 3 Codex를 fake app-server부터 구현하고 실제 로그인 스모크로 끝낸다.
6. 65분·8교시·깨끗한 Windows 설치는 사람 관문으로 수행한다.
7. 공개 전환·push·배포는 별도 승인과 공개 감사를 거친다.
