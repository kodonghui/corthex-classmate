# Gate D — 장애 복구

> 초안 · 2026-09-02 · 측정 전. 형식: 판정 → 측정값 → 재현 명령 → 결정에 미치는 영향 → 사람이 할 일.

## 판정

**측정 예정** — 자동 테스트 미작성. Phase 1 에서 다섯 가지 장애를 일으키고 **기록은 계속되고** 최근 수초 이내 손실로 복구되는지 확인한다.

## 장애 목록과 기대 동작

| 장애 | 기대 동작 | 사용자에게 보이는 것 |
|---|---|---|
| 사이드패널 닫기 → 열기 | 서비스워커·도우미는 계속 기록. 다시 열면 마지막 상태 복원 | 기록 그대로, NowLine 갱신 |
| 공유 페이지 새로고침 | content script 재주입 → 누락 없이 이어 붙임(중복 문단 제거) | SourceFooter "전사 n초 전" 회복 |
| 캡처 중단(탭 닫힘) | 전사·질문 기록은 계속. 화면만 "자료 지연" | 호박색 한 줄 + 행동 하나("Meet 탭에서 다시 시작") |
| 도우미 프로세스 강제 종료 → 재시작 | SQLite WAL 로 최근 수초 이내 손실. 확장이 재연결 | 잠깐 호박색 → 초록 |
| 제공자 응답 실패 | 질문·문맥은 저장(queued). 복구 시 답 완성(recovered) | "튜터 답변이 잠시 멈췄어요. 수업 기록과 질문 지점은 계속 저장하고 있어요. 연결되면 설명을 완성해 둘게요." |

기준(§3-6): 60분 기록에서 복구 불가 손실 0건, 재시작 시 최근 수초 이내.

## 재현 명령 (작성 예정)

```bash
cargo test --manifest-path apps/native-host/Cargo.toml recovery::   # WAL 검증 · 강제 종료 시뮬레이션
pnpm --filter @classmate/browser-extension test -- recovery         # 새로고침·패널 재열기 시뮬레이션(모의)
```

## 결정에 미치는 영향

- 교시마다 독립 세션 파일(8시간 단일 세션 금지) 을 전제로 WAL 체크포인트 간격을 정한다.
- 오류 상태 문구는 §3-5 그대로 쓰고 fixtures 의 `answer.failed` payload.message 와 일치시킨다.
