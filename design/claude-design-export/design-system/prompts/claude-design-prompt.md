# Claude Design용 프롬프트 — Corthex Classmate 사이드패널 완성

이 디자인 시스템을 첨부한 뒤, 아래 내용을 그대로 붙여 넣으세요.

---

Corthex Classmate 사이드패널의 실제 화면을 이 디자인 시스템으로 완성해 주세요.

## 0. 이 작업의 성격
새 방향을 발산하는 단계가 아닙니다. 디자인 시스템에 이미 정해진 상호작용 모델 **"단어 잡기"**를 제품 수준의 인터랙티브 프로토타입으로 완성하는 단계입니다. 방향을 바꾸거나 여러 안을 만들지 마세요. 역할은 학습 도구 UX 디자이너입니다.

## 1. 시작 전에 읽을 것
- `readme.md` 전체. 특히 "The interaction model — 단어 잡기", "CONTENT FUNDAMENTALS", "VISUAL FOUNDATIONS".
- `components/classmate/*.prompt.md` — TranscriptFlow, MarginNote, GuessList, NowLine, SourceFooter, CodeCompare, MomentRow, AnswerCard 사용법.
- `ui_kits/sidepanel/` — 참고 구현. 구조와 문구를 따르되 더 다듬어도 됩니다. 전사 데이터는 `ui_kits/sidepanel/data.jsx`의 `CM_TRANSCRIPT`, `CM_ANSWERS`를 그대로 써도 됩니다.
- `explorations/` — 과거 발산 자료. 참고만 하고 그 방향으로 바꾸지 마세요.

## 2. 만들 것
인터랙티브 HTML 프로토타입 하나. 380 × 900px **데스크톱 Chrome 사이드패널** 프레임 안에서 아래 화면과 상태가 실제 클릭으로 이어져야 합니다. 휴대폰 베젤·모바일 목업 금지.

A. **듣는 중** — 선생님 전사가 아래에서 흐르고(TranscriptFlow, 최근 4–5문장, 마지막 두 문장만 진한 잉크), 인식된 용어에 점선 밑줄, 헤더는 44px(상태 점 · 주제 · 3교시 · 시계), 맨 아래 SourceFooter 한 줄. 이 화면에 버튼은 없습니다.
B. **붙잡은 직후** — 점선 단어를 누르면 그 문장 바로 아래에 MarginNote(preparing, "한 줄로 정리하고 있어요"). 누른 단어는 잉크 배경 + 실선 밑줄.
C. **한 줄 답변** — MarginNote(ready): 단어 · 시각, 한 문장 결론, 근거 태그, 빠른 요청 칩 3개, "자세히 보기 ▸", "18초 뒤 접혀요 · 기록에 남아요". 메모 아래에 NowLine "지금 · 생성자 주입 코드로 넘어갔어요". 칩을 누르면 결론이 그 자리에서 바뀌고(더 쉽게 → 비유, 내 코드와 비교 → CodeCompare 두 줄) 근거 태그도 그에 맞게 바뀝니다.
D. **문장을 붙잡음** — 문장 본문을 누르거나 Alt+S → MarginNote(choosing) 안에 GuessList "혹시 이게 막혔나요?" 2–3개 → 하나 고르면 C로.
E. **접힌 메모** — 18초 뒤 메모가 점선 한 줄(단어 · 시각 · 결론 앞부분)로 접히고, 누르면 다시 펴집니다. 전사는 그 아래로 계속 흐릅니다.
F. **자세히** — 붙잡은 문장(TranscriptFlow size="md", 시각 표시), AnswerCard: 결론 + 근거 태그 + 접힌 섹션(왜 그런가요 / 내 코드와 비교 / 선생님 화면 코드 / 선생님이 말한 부분) + 후속 칩. 하단 고정 바에 NowLine과 primary 버튼 **"수업으로 돌아가기"** 하나. 텍스트 입력창은 이 화면 맨 아래에만, 칩 뒤에.
G. **기록** — SourceFooter의 "기록 N"을 누르면 진입. MomentRow를 교시별로 묶고 헤어라인만으로 구분. 카드·화살표 아이콘 없음.
H. **연결 문제 두 가지** — (1) 전사 멈춤: 새 문장이 멈추고 SourceFooter가 호박색으로 "전사가 잠시 멈췄어요. 화면과 코드는 계속 기록하고 있어요. 다시 연결". (2) 튜터 멈춤: 붙잡은 메모가 호박색 대기 상태("튜터가 돌아오면 여기에 한 줄이 나타나요 · 순간은 저장됐어요"), SourceFooter는 빨간색으로 "튜터 답변이 잠시 멈췄어요. 수업 기록과 질문 지점은 계속 저장하고 있어요." 모달·배너 금지.

## 3. 실제 내용 — 그대로 사용, 바꾸지 말 것
- 주제: IoC 컨테이너와 의존성 주입 · 3교시
- 최근 전사: "객체를 직접 new로 만들면 클래스끼리 강하게 묶입니다." → "이제 생성 책임을 컨테이너에 맡겨 볼게요."
- 사용자의 막힌 지점: 왜 new로 직접 만들면 안 되는지 모르겠어요.
- 질문 시각: 10:32:18 · 현재 파일: OrderService.java
- 자료 시점: 전사 4초 전 · Meet 화면 2초 전 · IntelliJ 1초 전
- 한 문장 답변: new 자체가 틀린 것은 아니지만, 객체를 바꾸거나 테스트하기 어려워지기 때문에 생성 책임을 분리합니다.
- 선생님의 현재 진행: 선생님은 지금 생성자 주입 코드로 넘어갔어요.
- 빠른 요청 칩: 방금 내용 · 더 쉽게 · 지금 화면 코드 · 내 코드와 비교 · 왜 필요한데? (한 메모에 3개까지)
- 근거 문구: 확인됨 · 일부 확인 · 추론 · 자료 지연 (Evidence type = verified / partial / inferred / delayed)
- 연결 문제 문구: 튜터 답변이 잠시 멈췄어요. / 수업 기록과 질문 지점은 계속 저장하고 있어요.
- 추가 문구가 필요하면 `readme.md`의 CONTENT FUNDAMENTALS를 따르세요: 해요체, 붙잡다·접히다·남다·돌아가다, 느낌표 없음, 사용자 호칭 없음, 튜터가 자신을 "저"라고 부르지 않음, 실제 제품에 넣을 수 있는 수준.

## 4. 규칙
- 한 화면에 가장 중요한 행동은 하나. 듣는 중 화면에는 채도 있는 블록이 0개, 자세히 화면에만 primary 버튼 1개.
- 전사가 화면에서 가장 큰 글자(`--type-transcript`, 19/31). 헤더·상태줄·메타는 작고 회색.
- 결론이 먼저, 근거 태그는 모든 주장에, 자세한 설명은 접어 두기.
- 토큰(`styles.css`)과 컴포넌트만 사용. 새 색·새 폰트·그라데이션·이모지·AI 느낌 아이콘(sparkles, bot, brain) 금지. 카드 그림자 금지. 아이콘은 최소(듣는 중 화면엔 설정 아이콘 하나).
- 새 컴포넌트가 정말 필요하면 만들되, 왜 기존 것으로 안 되는지 한 줄로 적어 주세요.
- 데스크톱: hover와 키보드 포커스 상태를 실제로 구현. Alt+S로 마지막 문장을 붙잡기.
- 360px 폭에서 한국어 단어가 중간에 끊기지 않게(`word-break: keep-all`), 520px에서 줄 길이가 너무 길어지지 않게(전사 최대 폭 제한).

## 5. Tweaks(트윅) 패널로 노출할 것
- 패널 폭: 360 / 380 / 520
- 전사 끊김 on/off · 튜터 끊김 on/off
- 메모 자동 접힘(18초) on/off
- 답변 길이: 한 줄만 먼저 / 바로 자세히

## 6. 시연 동작
- 수업 시계는 10:32:10에 시작해 1초씩 흐르고, 전사 문장이 시각에 맞춰 실제로 도착합니다(`CM_TRANSCRIPT`의 `at` 값).
- 단어를 붙잡으면 1.6초 뒤 답변, 18초 뒤 접힘. 시연 컨트롤은 패널 **바깥**에 두고 패널 안에는 제품 UI만.

## 7. 완료 기준 — 스스로 확인하고 결과에 짧게 답해 주세요
1. 듣는 중 화면을 처음 봤을 때 채팅창이나 대시보드로 보이지 않는가.
2. 글자를 한 자도 입력하지 않고 답을 받을 수 있는가.
3. 답을 읽는 동안 선생님이 지금 어디 있는지 항상 보이는가.
4. 모든 주장에 근거 태그가 붙어 있는가.
5. 연결 문제일 때 무엇이 멈췼고 무엇이 계속되는지 한 줄로 보이는가.
6. 360px에서 잘리거나 겹치는 요소가 없는가.
